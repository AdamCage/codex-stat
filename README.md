# Сбор статистики Codex

Скрипты читают локальные журналы активных и архивных сессий Codex, включая файлы `.jsonl.zst`, и формируют CSV с одной строкой на сессию. Сбор начинается с 1 сентября 2026 года, 00:00 по Москве. Учитываются запросы, начатые с этой даты. Если журнал не содержит времени начала, используется время доступной записи. Для более ранних сессий в CSV попадают только данные за выбранный период. Тексты сообщений в CSV не попадают.

## Запуск

Нужен Node.js 22.15 или новее. PowerShell на Windows может использовать Node.js из установленного пакета Codex Desktop, если команды `node` нет в PATH. Для обеих версий можно задать путь к Node.js через переменную `CODEX_NODE`. Откройте терминал в папке со скриптами.

**Windows PowerShell**

```powershell
.\collect-codex.ps1
```

**macOS и Linux**

```bash
bash collect-codex.sh
```

На вопрос «Статистика по ИИ-прокси?» ответьте `y` для прокси или `n` для прямого подключения. Ответ задаёт значение `is_proxy` для всей выгрузки.

Скрипт показывает, где ищет журналы, сколько файлов прочитал, сколько повторных записей ответов обнаружил и куда сохранил результат. По умолчанию он ищет журналы в `CODEX_HOME` или в папке `.codex` вашего профиля и сохраняет CSV под именем `<имя пользователя>.csv` в текущей папке. Существующий CSV с тем же именем перезаписывается.

## Путь к файлу и журналам

Введите имя или путь к CSV в ответ на первый вопрос скрипта. Например, `sessions` создаст `sessions.csv`. Нажмите Enter для имени пользователя. При необходимости путь к журналам можно передать при запуске:

```powershell
.\collect-codex.ps1 -CodexPath 'C:\путь\к\.codex'
```

```bash
bash collect-codex.sh "$HOME/.codex"
```

## Столбцы CSV

| Столбец | Значение |
| --- | --- |
| `datetime` | Начало сессии или самая ранняя доступная связанная отметка, в UTC. |
| `session_id` | Идентификатор сессии Codex. |
| `input tokens` | Сумма входных токенов по уникальным ответам модели. |
| `output tokens` | Сумма выходных токенов по уникальным ответам модели. |
| `ttft` | Медианное время от начала успешного запуска до первого токена, в секундах. |
| `tps` | Выходные токены за секунду полного времени успешных запусков, для которых доступны счётчики и длительность. Время включает ожидание и работу инструментов. |
| `is_proxy` | `1` для ответа `y`, `0` для ответа `n`. |

| `status` | `error`, если в сессии записана ошибка запуска. Иначе `succes`. |
| `details` | Уникальные сообщения об ошибках из журнала, по одному на строку внутри ячейки. Для `succes` поле пустое. |

Ошибка остаётся в истории сессии, даже если следующий запуск завершился успешно. Отмена без ошибки сама по себе не меняет статус.

Если журнал не содержит данных для расчёта метрики, соответствующая ячейка остаётся пустой.

## Сводка после выгрузки

После записи CSV скрипт печатает имя пользователя ОС, период в UTC, число запусков Codex и долю успешных среди всех обнаруженных запусков, включая прерванные и незавершённые. Один запрос в сводке соответствует одному запуску Codex и может включать несколько обращений к модели. Имя пользователя служит подписью для локальных данных, включая субагентов. В таблице сводки среднее, медиана и число измерений приводятся отдельно для входных и выходных токенов, TTFT и TPS по успешным запускам с доступными измерениями.
